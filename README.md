## 프로젝트 개요
`GameCoding_Zelda`는 C++로 작성된 네트워크 게임 서버와 예제 클라이언트(더미 클라이언트)를 포함한 학습용 프로젝트입니다. IOCP 기반의 네트워크 구조와 Google Protobuf를 활용한 패킷 직렬화를 통해 간단한 방(Room) 기반 게임 로직을 구현합니다.
- **GameCoding Zelda**는 IOCP 기반의 C++ 게임 서버와 Win32 클라이언트 샘플, 그리고 부하 테스트용 더미 클라이언트를 포함한 실시간 방(Room) 기반 액션 RPG 학습 프로젝트입니다.

- 서버는 `127.0.0.1:7777` 포트를 수신하며 Google Protobuf로 정의된 패킷을 직렬화해 세션 간 상태를 동기화합니다.
## 개발 환경 및 의존성
- 클라이언트는 Win32 기반 게임 루프와 더블 버퍼링 렌더링을 제공하며, 동일한 네트워크 코어를 활용한 더미 클라이언트는 멀티 세션 부하 시나리오를 재현합니다.
- **Visual Studio 2022** (v143 툴셋)

- **Windows 10 SDK**
## 주요 구성 요소
- **Google Protobuf** 라이브러리 (프로젝트 내 `Server/Libraries/Include/google/protobuf`)
### 서버 (Server/)

- **ServerService & IOCPCore**: IOCP 기반 네트워크 코어를 초기화하고 수락 스레드 및 작업 스레드를 관리합니다.
## 빌드 방법
- **GameSession / GameSessionManager**: 접속/해제 이벤트를 처리하고 세션 리스트에 대한 스레드 안전한 추가·제거 및 브로드캐스트를 담당합니다.
1. Visual Studio 2022에서 솔루션 열기
- **GameRoom**: 초기 몬스터 스폰, 타일맵 로딩, 플레이어 입장/퇴장 처리, 이동 검증, 피해 계산 및 전파를 수행하는 핵심 게임 루프를 구현합니다.
   - 서버: `Server/Server.sln`
- **GameObject / Player / Monster**:
   - 클라이언트(더미): `Server/Client/GameCoding.sln` 또는 `Server/DummyClient/DummyClient.vcxproj`
  - `GameObject`는 오브젝트 ID 발급, 위치/방향/상태 브로드캐스트 유틸리티를 제공합니다.
2. 원하는 구성(Debug/Release, x64)으로 빌드합니다.
  - `Player`는 전방 셀의 몬스터를 탐색하는 스킬 판정과 공격력 기반 피해 처리를 수행합니다.
3. 빌드 결과 실행 파일은 각 프로젝트의 `Debug` 또는 `Release` 폴더에 생성됩니다.
  - `Monster`는 가장 가까운 플레이어 추적, 이동/공격 상태 전환, 간단한 경로 탐색 AI를 포함합니다.

- **Tilemap**: 텍스트 기반 맵 파일(`Tilemap_01.txt`)을 로드해 타일 속성과 보행 가능 여부를 구성하고, 서버의 AI/충돌 판정을 지원합니다.
## 실행 예시
- **ServerPacketHandler**: 이동, 오브젝트 생성·삭제 등 주요 프로토콜 메시지를 해석·생성합니다.
### 서버 실행

```cmd
### Win32 클라이언트 (Server/Client/GameCoding/)
> Server.exe
- **Game**: 시간·입력·씬·네트워크 매니저를 순차적으로 업데이트하고 더블 버퍼링 렌더링을 담당하는 메인 루프입니다.
```
- **NetworkManager**: IOCP 클라이언트 서비스를 초기화하고 매 프레임 누적된 패킷을 디스패치하며 송신을 처리합니다.
- 기본적으로 `127.0.0.1:7777` 포트에서 대기합니다.
- **ClientPacketHandler**: 서버에서 수신한 입장/오브젝트/이동 패킷을 해석해 씬 상태와 플레이어 정보를 갱신합니다.
- 종료 시에는 콘솔에서 `Ctrl+C`를 눌러 안전하게 종료합니다.
- **SceneManager & DevScene**:
  - 씬 전환과 현재 씬의 업데이트/렌더링을 관리하고,
  - 개발용 씬에서는 텍스처·사운드 로딩, 몬스터 스폰, HUD 렌더링, 플레이어/몬스터 오브젝트 관리를 수행합니다.
- **MyPlayer**: 입력에 따라 이동 가능 여부를 확인하고, 방향·무기·상태를 전환한 뒤 변경 사항을 서버와 동기화합니다.

### 더미 클라이언트 (Server/DummyClient/)
- IOCP 클라이언트 코어를 활용해 다수의 세션을 생성하고 멀티 스레드로 디스패치를 반복함으로써 서버 부하 테스트를 지원합니다.
- `ClientPacketHandler`는 Protobuf 메시지를 파싱해 간단한 패킷 로그를 출력합니다.

## 네트워크 및 프로토콜
- 패킷 포맷은 `[size][id][payload]` 구조를 따르며, `Protocol.pb.h`로 생성된 메시지를 사용합니다.
- 서버는 디스패치 루프 이후 게임 룸 업데이트를 실행해 모든 세션에 변경된 오브젝트 상태를 브로드캐스트합니다.
- 클라이언트는 `_dirtyFlag`를 통해 이전 프레임 대비 변경된 입력만 서버로 전송해 네트워크 부하를 최소화합니다.

## 리소스 및 데이터
- 클라이언트 리소스는 `Server/Client/GameCoding/Resources/` 하위에 배치되며 다음과 같이 구분됩니다.
  - `Sprite/`, `Sound/`, `Tilemap/`, `Data/`
- 서버는 타일맵 로딩 시 해당 경로에서 텍스트 맵 파일을 읽어 게임 룸을 구성합니다.

## 빌드 및 실행 방법
### 공통 준비
1. **Visual Studio 2022**(v143 툴셋)와 **Windows 10 SDK**, 프로젝트에 포함된 **Google Protobuf** 헤더/라이브러리를 사용합니다.
2. 솔루션을 열 때 필요한 서브모듈이나 외부 의존성은 리포지토리에 포함되어 있으므로 추가 설치는 필요하지 않습니다.

### 서버
1. Visual Studio에서 `Server/Server.sln`을 엽니다.
2. 구성(예: `Debug|x64`)을 선택한 뒤 빌드합니다.
3. 실행하면 기본적으로 `127.0.0.1:7777`에서 클라이언트 접속을 대기합니다.
4. 종료 시 콘솔에서 `Ctrl+C`로 안전하게 종료합니다.

### Win32 클라이언트
1. `Server/Client/GameCoding.sln`을 열고 원하는 구성으로 빌드합니다.
2. 실행 시 `127.0.0.1:7777` 서버에 접속하며, 게임 루프에서 IOCP 디스패치를 수행합니다.
3. HUD에 플레이어 위치·스탯이 표시되며 입력에 따라 이동/공격이 동작합니다.

### 더미 클라이언트
1. `Server/DummyClient/DummyClient.vcxproj`를 빌드합니다.
2. 실행하면 지정한 스레드/세션 수로 자동 접속해 패킷 로그를 출력하며 부하 시나리오를 재현합니다.

## 개발 팁
- 게임 룸은 IOCP 디스패치 이후 업데이트되므로 새로운 로직을 추가할 때 세션 락 정책과 브로드캐스트 범위를 고려하세요.
- 서버와 클라이언트 모두 멀티 스레드로 동작하므로 공유 컨테이너 접근 시 락이나 락 프리 자료구조 사용을 검토합니다.
- 네트워크 패킷 추가 시 Protobuf 정의를 갱신하고 서버/클라이언트 핸들러를 동시에 수정해야 합니다.
